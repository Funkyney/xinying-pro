# 心影网页适配器维护

适配器只使用网页上用户可见、可操作的 DOM 元素，不请求心影未公开接口，也不读取 Cookie 或 Token。

## 结构

- `config/xinying-selectors.json`：可更新的定位规则与人工检查点文案。
- `src/main/playwright-adapter.ts`：登录检测、生成提交、虚拟人像审核、任务观察和下载。
- `src/main/platform-view.ts`：心影官方页面、飞书登录会话与兼容模式。
- `src/main/job-worker.ts`：本地队列和人工接管状态机。

## 页面改版后的处理顺序

1. 在“原网页模式”确认登录和功能本身可用。
2. 不提交任务，只观察提示词输入框、文件输入框和生成按钮的可访问属性。
   开发版或解压版 APP 运行时，可以执行 `npm run inspect:platform` 导出经过账号信息隐藏的可见控件清单。
   需要只读打开指定心影页面时，可临时设置 `XINYING_INSPECT_URL`；脚本只接受 `https://blueaivideo.com` 域名，并同时输出主要适配器控件计数：

   ```powershell
   $env:XINYING_INSPECT_URL = "https://blueaivideo.com/avpAgent?projectId=…&sessionId=…"
   npm run inspect:platform
   Remove-Item Env:XINYING_INSPECT_URL
   ```
3. 优先更新 `config/xinying-selectors.json`，避免修改业务代码。
4. 定位规则应优先使用稳定的 `data-*`、`aria-label`、`placeholder` 或明确文案；不要使用坐标和深层 `nth-child`。
5. 使用无敏感信息的测试项目验证素材顺序、模型、比例、分辨率、时长、声音、提示词和参数。
6. 在实际扣费提交前，由用户检查预览并明确确认。

分辨率值 `auto` 是本地适配器哨兵，不会作为文字点击心影页面。使用 `auto` 时保持当前模型页面已有的分辨率；显式值必须存在于 `src/shared/model-profiles.ts` 并能在当前心影参数面板精确回读。2026-08-21 实机标定：Seedance 2.5 全能参考支持 480p/720p/1080p、4–30 秒；Seedance 2.0 全能参考支持 480p/720p/1080p/4k、4–15 秒；两者支持 9:16、16:9、4:3、1:1、3:4、21:9、自适应和声音开关。

## 参考素材顺序

SQLite 中 `reference_assets.position` 是唯一顺序来源。提交快照按 `position` 升序保存。心影当前图片输入控件不支持一次选择多张，Playwright 必须逐张设置单文件输入，并在每次上传后确认素材槽位数递增，最后再次核对总数。任何适配器修改都必须保留这一不变量。

任务入队时会把参考图复制到 `%APPDATA%\xinying-director\job-snapshots\<job-id>`，`jobs.references_json` 指向这些不可变副本并保留原 SHA-256。适配器只能读取任务快照，不能在执行时重新读取项目当前素材；这样项目后续替换、重排或删除不会改变已排队任务。

Windows 原生多选文件框不保证保留点击顺序。桌面端批量替换会将所选文件按文件名自然排序，并在写入前展示完整的 `@图N ← 新文件` 映射；用户确认后才替换，取消不产生任何改动。CLI 的 `refs batch-replace --file ...` 则严格使用命令行参数顺序。

验证建议：使用文件名明显不同的测试图，确认 APP 的 `@图1..N` 与心影页面显示顺序一致。若心影异步上传后自行重排，应暂停自动提交，并在适配器中增加页面顺序核对。

2026-08-21 实机验证：同一单文件输入控件连续设置三张测试 PNG 后，心影素材槽位依次显示“图1、图2、图3”，且每一步槽位数按 1、2、3 递增。验证期间提示词为空、消息数不变，结束后通过每项 `.content-delete` 清空草稿。

## 空间与项目

首页 `.selector-trigger` 展开 `.THeaderPopper.-selector`。空间卡为 `.selector-team-item`，其中“个人空间 / 数据不与他人互通”映射为私有空间，其余卡映射为团队空间；项目卡为 `.selector-project-item`，名称和 `ID：短 ID` 是目录稳定标识。切换空间会打开该空间项目列表并更新心影当前上下文；切换项目后必须从 URL 回读完整 `projectId`，再进入 `/avpAgent` 并等待 `sessionId` 与创作区同时出现。

新建项目前先激活目标空间的一个现有项目，确保心影全局“新建项目”按钮把项目建在正确空间。个人空间表单只有名称和“视频创作类型”；团队空间还包含“所属客户”。存在的字段必须精确选择真实选项，确认按钮可用后才提交。若目标空间没有任何可激活项目或页面无法回读新项目 `projectId`，适配器应停止并报告，不得猜测空间或项目编号。

全新项目首次进入 `/avpAgent?projectId=…` 时可能尚无 `sessionId`，但创作区已可用。适配器应允许保存这种项目链接；第一次点击生成前记录 `uninitialized` 防重复标识，提交后再从地址栏回读真实 `sessionId`。监控或重启恢复时若任务标识已有会话 ID，应将其补回项目 URL 后导航，不能把首轮无会话 ID 误判为页面错误。

## 虚拟人像

虚拟人像流程分为同步调用、远端管理和上传审核三条路径。同步路径从当前项目内容生成页的“+V角色”打开心影认证角色库，读取 `.faceCard` 名称、预览、稳定素材标识和 `.icon-shanchu` 删除权限标记，按页面原始顺序保存到当前空间缓存；团队空间缓存对应该团队成员共享库，不能与个人空间混用。角色总库可能包含数千个公共和团队角色，因此适配器先在“全部”来源下保留常用的最新窗口，再通过页面可见“筛选 → 来源 → 上传人像 → 确定”完整读取账号可管理的人像，并保存独立 `deleteSortOrder`；退出前恢复“全部”，避免影响后续生成选角。页面未提供可靠创建时间，因此 APP 的“最新 / 最早上传优先”只反转相应页面原始顺序，不伪造时间戳。远端管理只接收同一空间、当前可用且 `canDelete=true` 的角色；删除前同样切到“上传人像”并加载完整清单，逐项点击卡片删除入口，且仅在同一弹层同时出现“确定删除角色”“删除后，角色将不可恢复。”和可用的“确定”按钮时继续。每项确认从页面消失后才处理下一项；若中途失败，已成功删除的角色仍会从本地缓存和相关项目的实时素材清单中移除，未处理项保持不变。生成任务快照不会追溯修改。生成任务读取 `materialOrder`，按最终顺序上传本地图，并在虚拟人像连续分组的位置按保存顺序点击卡片的 `.p-checkbox-black`，确认“已选 N 项”后点击“确定”。2026-08-21 实机验证心影会把多个虚拟人像作为一个连续分组重新插入：先加入“人像 A → 本地图”，再选人像 B 后，官方顺序变为“本地图 → 人像 B → 人像 A”，且素材卡没有可用拖拽属性。0.3.4 允许桌面端自由穿插并保存任意 `materialOrder`，但在不连续的 V 角色顺序下显示即时提示并阻止错误提交；连续分组仍可整体位于本地图之前、中间或之后。上传路径标定到所选项目的 `/aiCharacter`“新建虚拟人像”表单：名称自动取素材文件名，性别、年龄、人种默认“其他”，应用范围默认国内版。普通参考图可先复制到本地人像区再走同一审核队列。只有素材在 APP 中记录了明确合规确认时，适配器才会填表、勾选“我已阅读并同意”并点击“确定”；字段、承诺或提交状态无法严格回读时仍进入 `needs-human`。CLI 可用 `portrait platform-sync --project-id` 更新空间缓存、`portrait platform-list --workspace-id` 读取缓存、`portrait platform-delete --project-id ... --ids ... --confirm` 永久删除可管理角色，用 `project update --portrait-ids ... --material-order ...` 配置自动调用顺序。

2026-08-21 基线实机验证：合成成年头像经人工确认后已成功入库为“合成测试人像-0821”。本次 0.2.0 实机探测进一步确认：当前账号的认证角色库可从生成页读取 45 个可见角色；点选 `.p-checkbox-black` 后页面显示“已选 1 项”，点击“确定”后角色以“图1”进入素材槽位，重载页面后测试草稿已清空。自动合规提交只用于用户在 APP 明确记住声明后新建的任务。

0.3.5 的参考图授权使用 `sourceReferenceId` 保证幂等，同一参考图的活动或已完成审核任务必须直接复用。Element Plus 的三个资料下拉框需要真实指针事件打开；选项可在 DOM 中精确选择，年龄与人种的末尾“其他”还要先滚动对应弹层，且相邻下拉框之间要等待关闭动画完成。成功提交后保存 `portrait:<job-id>`，任何恢复都只能检查角色库，禁止再次提交。角色名必须对 `.face-name-text` 做完整相等比较，不能让同名 `_1` 卡片遮蔽精确结果；短时未找到保持 `running`。后台队列通过屏幕外有效视口运行，只有用户主动进入“原网页模式”才显示心影页面。

## 真实页面标定（2026-08-20）

- 生成区：`.ContentChatInput`
- 提示词：`.mention-editor[contenteditable=true]`
- 参数面板：`.ContentChatOptionItem._popover` → `.ContentChatOptionItemPopover`
- 发送：`.btn-send:not(.disabled)`
- 对话配对：`.ContentChatListItem.userChat` 后的 `.agentChat`
- 视频结果：`.content-item._video`
- 下载：结果卡内 `.icon-xiazai`
- 角色库：`/aiCharacter` → “新建虚拟形象” → “本地上传” → `.createCharacter`

这些类名来自可见页面 DOM，不是未公开接口。页面改版后先更新选择器包并重新做只读诊断。

生成会话从首页切换后，页面实测可能需要约 7–10 秒才挂载创作区。适配器最多等待 20 秒，不应把固定的数百毫秒延时改回立即判断，否则冷启动会被误报为页面改版。

下载按钮位于结果卡的内部滚动容器中，可能被 Playwright 判为在顶层视口之外。适配器应先从 `.icon-xiazai` 上溯到对应 `.btn-option`，再触发该已定位节点自身的 `click` 处理器；不要改成坐标点击。Electron 会在点击前登记一次性下载捕获，通过 `will-download` 保存到受管结果目录，并在失败或超时后清理等待状态。2026-08-21 已用既有真实结果验证该链路，临时下载副本随后删除。

`WebContentsView` 在 APP 的其他页面中通常处于隐藏状态，隐藏后心影页面的 CSS 视口会变为 `0×0`。队列提交和状态监控必须通过 `PlatformViewManager.withAutomationViewport()` 临时挂载有效视口，再执行模型弹层、参数面板、上传和结果下载；结束后按用户当前页面恢复可见性。模型名称会在会话加载后异步回填，切换前先等待 5 秒确认当前值。时长控件是 Vue/Element Plus 组合控件，必要时使用原生 `value` setter 并派发 `input`、`change`、`blur`，随后回读摘要；不能对 `aria-disabled` 的内部数值框直接调用 Playwright `fill`。

`.content-item._video` 同时用于真实结果和“生成中...”占位卡。带 `_isLoading`、运行中文案，或既无媒体地址也无下载控件的卡片必须保持 `running`；只有存在媒体或结果卡下载控件时才能判为 `completed`。

生成按钮点击前必须先把 `pending-chat:<projectId>:<sessionId>:<userIndex>` 写入任务。若 APP 在点击前后退出，启动恢复会保留该标识并进入人工检查；用户确认后恢复时，适配器先查找该索引是否已经出现用户消息，命中则直接转入状态监控，不得再次点击生成。心影重载后可能只保留最近 10 轮消息，使原始索引向前漂移；如果原索引内容不再匹配，必须在同一 `sessionId` 内以任务的完整 `promptSnapshot` 从后向前回退匹配，并把最终任务标识更新为当前索引。提交与运行监控共享同一个串行锁，禁止两个定时轮次同时操作心影页面。

## 人工检查点

`humanCheckpointTexts` 命中时，任务会转换为 `needs-login` 或 `needs-human`。不得删除检查点来强行自动运行；应先判断平台是否增加了新的安全步骤。
